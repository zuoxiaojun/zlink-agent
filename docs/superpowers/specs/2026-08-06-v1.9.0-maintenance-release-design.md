## 4. 详细设计

### A-1（M-1）审批拒绝的工具卡片显示"已拒绝"而非"执行失败"

**方向**：给 `ToolExecutionEnd` 增加显式 `denied` 标记（比前端匹配"用户拒绝了操作"文本更稳健），逐层透传到前端卡片状态。hook 拦截路径（`_prepare` 返回 immediate，不下发卡片）保持不变，本项只覆盖审批拒绝路径。

1. **`agent/core/kernel_types.py`**：`ToolExecutionEnd` 增加字段 `denied: bool = False`（dataclass 带默认值，所有现有构造点零改动）。
2. **`agent/core/tool_dispatcher.py`**：
   - 新增内部 `_HandlerResult`（dataclass：`result: str`、`denied: bool = False`）；`_run_handler` 返回类型从 `str` 改为 `_HandlerResult`。denial 分支返回 `_HandlerResult(tool_error("用户拒绝了操作"), denied=True)`，其余所有返回路径 `denied=False`（桥工具、正常、approved、其他异常）。
   - `_dispatch_parallel._run` 返回 `(index, truncated, is_error, denied)`，`by_index` 存四元组；构造 `ToolExecutionEnd` 时透传 `denied=denied`。`ToolResult` 不变（transcript 里保持错误 JSON，`is_error=True` 语义不变）。
   - `_dispatch_sequential` 同样收集 `denied` 并传给 `ToolExecutionEnd`。
3. **`backend/api/chat.py`** `_on_event` 的 `tool_execution_end` 分支：`denied` 为 True 时在 `tool_result` 消息上附加可选字段：
   ```python
   payload = {"type": "tool_result", "name": event.tool_name, "result": event.result}
   if event.denied:
       payload["denied"] = True
   ```
4. **`web/src/types/index.ts`**：`WsServerMessage` 的 `tool_result` 增加 `denied?: boolean`。
5. **`web/src/hooks/useChat.ts`** `tool_result` 分支：`dispatch({ type: "REPLACE_PENDING_TOOL", name: msg.name, result: msg.result, denied: msg.denied })`。
6. **`web/src/context/AppContext.tsx`** `REPLACE_PENDING_TOOL`：替换 message 时若 `action.denied` 则带上 `_denied: true`（`Message` 类型增加 `_denied?: boolean`，同现有 `_tool_done` 前端临时标记模式）。
7. **`web/src/components/ToolStepCard.tsx`**：新增 `const denied = result?._denied === true;`，状态判定优先级 `denied > failed`：文案"已拒绝"、图标 `IconAlertTriangle`（或 `IconBan`）、class 追加 `tool-step-denied`。
8. **`web/src/styles/global.css`**：新增 `.tool-step-denied`（背景 `var(--warning-bg)`、边框/文字 `var(--warning)` 系），与 `.tool-step-error` 并列。

**测试**（`tests/test_tool_dispatcher_batch.py`）：扩展现有 `test_approval_blocked_denied_returns_denial`——通过 `_EventRecorder` 断言 emit 的 `ToolExecutionEnd.denied is True`、`ToolExecutionStart` 数量为 1、`ToolResult.is_error is True`；approved 用例断言 `ToolExecutionEnd.denied is False`。

### A-2（M-2）取消时会话持久化补全流式内容

**方向**：在取消路径把已流式生成的内容作为 partial assistant 消息补进 `_result_messages`（持久化数据），**不设置** `_final_response`——保持 WS `done` 消息与前端 UI 现状完全一致（HANDOFF 明确"仅影响持久化，不影响 UI"）。

1. **`agent/core/agent_adapter.py`**：
   - `run_conversation_async` 运行前初始化 `self._partial_response = ""`（每次 run 重置）。
   - `_call_llm_hook` 的 `_stream_cb` 末尾追加 `self._partial_response = "".join(_parts)`（`content_parts` 已在该闭包内，成本与现有 `partial` 构造一致）。
   - `except asyncio.CancelledError:` 分支在 `self._result_messages = list(self._agent.state.messages)` 后追加：
     ```python
     if self._partial_response:
         self._result_messages.append({"role": "assistant", "content": self._partial_response})
     ```
     注意：**不**改 `_final_response`（保持空），`completed` 仍为 False（`self._error = "用户已手动停止"` 已保证）。
2. **`backend/api/chat.py`** 持久化逻辑零改动：`result["messages"][len(history)+1:]` 自然切出 partial assistant 消息。

**已知局限（明确不在本次范围）**：取消发生在工具执行中时，已完成的 assistant tool_call 回合与 tool 消息同样不在 `state.messages` 中，本次只补流式内容；该局限与现状一致，不扩大改动面。

**测试**（`tests/test_agent_adapter.py`，扩展 `test_cancel_during_run_ends_with_agent_end` 或新增用例）：流式过程中触发 cancel → 断言返回 dict 的 `messages` 含一条 `role="assistant"` 且 content 等于已流式片段；`final_response` 为空串；`completed` 为 False。

### A-3（M-3）截断（桥）工具卡片 args 回退

**方向**：`effectiveArgs` 补回退链 + 桥工具 subtitle 增强，让 `tool_search`/`tool_describe`/`tool_call` 卡片至少有可见信息。

1. **`web/src/components/ToolStepCard.tsx`** `effectiveArgs` 改为回退链：
   ```ts
   const effectiveArgs = (() => {
     if (isPendingTool && result) {
       if (typeof result.content === "string" && result.content.trim()) return result.content;
       return call.function.arguments;   // 回退：pending 内容为空/空白时用 LLM 原始参数
   ```

2. **`extractSubtitle` 增加桥工具 case**（`tool_search` → `query`；`tool_describe`/`tool_call` → `name`），参数为空时卡片仍显示摘要行，避免"整卡无信息"的视觉空态。

### A-5（M-6）Agent 复用防御

**方向**：两个最小防御性修复（生产路径 chat.py 每次新建实例，属 latent 加固）。

1. **`agent/core/agent.py` `run_async`**：显式传入的新 token 始终采纳；未传且旧 token 已取消时重置为新 token，使 Agent 实例可复用：
   ```python
   if token is not None:
       self._token = token
   elif self._token.cancelled:
       self._token = CancelToken()
   ```
2. **`agent/core/agent.py` `subscribe`**：幂等化：
   ```python
   if listener not in self._listeners:
       self._listeners.append(listener)
   ```

**测试**（`tests/test_agent.py` / `tests/test_agent_loop.py`）：
- cancel 后用新 token 再次 `run_async` → run 正常完成（不再立即被旧取消态中断）；
- cancel 后不传 token 再 run → 同样正常完成；
- 同一 listener `subscribe` 两次 → 内部 listener 列表仅一条；`unsubscribe` 一次后不再收到事件。

   ```python
   def _resolve_env_path() -> Path:
       candidates = [Path(__file__).resolve().parent.parent / ".env"]  # dev：仓库根
       if getattr(sys, "frozen", False):
           candidates.insert(0, Path(getattr(sys, "_MEIPASS", "") or ".") / ".env")  # PyInstaller 包内
       for p in candidates:
           if p.exists():
               return p
       return candidates[0]  # 不存在时 load_dotenv 是 no-op
   load_dotenv(_resolve_env_path())
   ```

## 8. 决策摘要

- **顺序**：A → B → C → D；D 最后统一收口 v1.9.0，期间只提交不 bump 版本。
- **M-1**：`ToolExecutionEnd` 增加可选字段 `denied`（默认 False）逐层透传（tool_dispatcher → chat.py WS `tool_result.denied` → useChat/AppContext `_denied` → ToolStepCard 显示"已拒绝"）；hook 拦截路径保持无卡现状。选标记透传而非前端匹配文本，因更稳健。
- **M-2**：取消分支把 `_partial_response`（`_stream_cb` 累积）补进 `_result_messages`；**不**改 `_final_response`，UI 零变化；工具执行中取消的其余 transcript 丢失为已知局限，不扩大改动。
- **M-3**：`effectiveArgs` 回退链（pending 内容空白 → `call.function.arguments`）+ `extractSubtitle` 补三个桥工具 case。
- **M-5**：`_transform_context_hook` 两处 `_set_phase` 补 `session_id=self._session_id`。
- **M-6**：`run_async` 始终采纳显式新 token / 取消后自动重置新 token；`subscribe` 幂等。
- **M-7**：删除 `dispatch_tool` + re-export（已确认零引用）。
- **B**：根 `.env` 写 key（gitignored）；`backend/config.py` `.env` 查找 frozen-aware（`sys._MEIPASS` 优先）；`build-pyinstaller.sh` 加 `--add-data ".env:."`（带存在性守卫）；`main.js`/`backend_launcher.py` 不改（已核实生产路径）。
- **C-1**：`.page-container` 放宽到 1280px；列表页 `.card-grid`（auto-fill 320px）；配置页 `.form-grid-2`（auto-fit 340px）；McpPage 不改结构。
- **C-2**：按文件从多到少分批，纯静态样式机械迁移，动态样式不迁，每批 build+lint 门禁。
- **C-3**：ERP 测试结果条收敛为 `.test-result-ok/error` 类（全 `var(--success)`/`var(--danger)`）；`#fff` 白字属彩色底白字，保持现状。
- **C-4**：hash 徽章改中性灰（保留排障用途）；删除加 `window.confirm`。
- **范围外**：M-4（opencode 配置）、前端候选 5、旧内核回退、ERP/技能/记忆系统、既有 WS 字段、前端测试框架、后端鉴权、新依赖。
