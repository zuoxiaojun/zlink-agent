# 深度调研技能

当用户需要**系统性调研一个主题**时，比如市场分析、技术调研、竞品分析、政策解读等，按以下流程执行。

## 核心原则

1. **多源验证** — 不依赖单一来源，至少从 3 个独立来源交叉验证
2. **结构化输出** — 最终回答必须是结构化格式（表格、列表、分类）
3. **区分事实与推断** — 明确指出哪些是搜索到的数据，哪些是你的分析推断
4. **不跳过搜索** — 即使你认为知道答案，也要搜索确认最新信息

## 执行流程

### 阶段 1：明确调研问题

从用户的需求中分解出 3-5 个核心子问题。例如用户问"调研一下 AI Agent 在 ERP 中的应用"：

```
子问题 1: 目前有哪些主流 AI Agent 平台/框架
子问题 2: AI Agent 在 ERP 领域的具体应用场景
子问题 3: 国内外企业的实际落地案例
子问题 4: 技术路线对比（RAG vs Fine-tuning vs Agent）
子问题 5: 面临的挑战和限制
```

### 阶段 2：多角度搜索

对每个子问题分别搜索。搜索时使用不同的关键词组合：

```
第一轮：宽泛搜索 → 了解全貌
  web_search("AI Agent Enterprise Resource Planning 2026")
  
第二轮：精准搜索 → 深入具体
  web_search("AI agent ERP implementation case study")
  web_search("SAP AI agent strategy 2026")
  
第三轮：中文/本地化补充
  web_search("AI Agent ERP 应用案例 2026")
```

### 阶段 3：提取与交叉验证

对搜索结果进行：

1. **信息提取** — 使用 `web_extract` 提取关键页面的详细内容
2. **交叉验证** — 同一个信息点至少在两个独立来源中出现
3. **矛盾处理** — 如果来源存在矛盾，如实记录并标注差异

### 阶段 4：结构化输出

最终输出格式：

```markdown
## 调研主题：{题目}

### 概述
2-3 句话总结核心发现

### 详细分析
#### 1. {子问题 1}
- 关键发现：[数据/事实]
- 来源：[链接1]、[链接2]

#### 2. {子问题 2}
...

### 结论与建议
- 核心结论：...
- 建议行动：...

### 参考来源
1. [标题](url) — 发布日期
2. [标题](url) — 发布日期

> 调研时间：{日期}
> 声明：以上内容基于公开信息整理，部分分析为 AI 推断
```

### 阶段 5：事实核查

最终输出前做一次快速核查：

- 所有数据点是否都有来源？
- 是否有明确标注事实 vs 推断？
- 是否有相互矛盾的结论未说明？
- 是否有明显的信息缺口未提及？

## 适用场景

✅ **市场调研**：行业分析、市场规模、竞争格局
✅ **技术调研**：框架对比、技术选型、最佳实践
✅ **政策分析**：法规解读、政策影响评估
✅ **竞品分析**：产品功能对比、定价策略、用户评价
✅ **事件研究**：最新动态、背景调查、影响分析

## 不适用的场景

❌ 需要内部数据/权限的调研（如公司财务数据）
❌ 实时数据查询（如股票价格、天气、物流跟踪 — 这些应直接回答）
❌ 主观意见征集（如"哪个产品更好"）
