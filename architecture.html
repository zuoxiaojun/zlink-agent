1. 项目总览

核心理念：让企业用户通过自然语言直接与 ERP 系统交互——"帮我查库存"、"列出待审批的销售订单"、"这个月采购了多少原料？"——Agent 自主选择合适的工具查询 YonSuite 并整合结果回答。

后端

FastAPI 应用（端口 8089），WebSocket 长连接 + REST API。核心是 AIAgent 类的同步工具调用循环，通过 OpenAI 兼容 API 调用 LLM，Stream 模式逐 token 返回文本。

前端

React + Vite（端口 8088），React Router 多页面 SPA。WebSocket 流式接收 AI 回复，ReactMarkdown 渲染。侧边栏导航，会话历史持久化刷新恢复。

3. 请求全链路流转

1

用户输入 → WebSocket 发送

前端 ChatPage 追加用户消息到本地 messages[]，通过 WebSocket /ws 发送 JSON（含 message、sessionId、config）。Vite 代理 /ws 到后端 8089。

2

System Prompt 组装

backend/api/chat.py 收到 WebSocket 消息后调用 AIAgent.run_conversation()。Agent 构建系统提示，拼接：基础安全指令 + 对话摘要回顾（memory_manager）+ 自主记忆注入（fact_memory）+ 已激活技能指令（SKILL.md）+ 全部工具 Schema。

3

工具调用循环

Agent 进入 while 循环（最大 max_iterations 次）：调用 LLM（流式）→ LLM 返回 text（结束循环输出给用户）或 tool_calls（执行工具，结果追加到消息历史，继续循环）。每轮 Token 用量累加。

4

工具调度执行

当 LLM 要求调用工具时，ToolRegistry.dispatch() 执行：before-hook 链（安全检查）→ handler 函数（如查询 YonSuite API、执行 bash 命令、读写文件等）→ after-hook 链（审计日志）→ 结果截断后返回 LLM。

5

流式返回前端

每收到 LLM 的 text chunk 立即通过 WebSocket 推送给前端。前端实时渲染 Markdown，工具调用过程折叠在 details/summary 中展示。

6

对话收尾

Agent 回复完成后：保存会话到 data/sessions/ → 更新 FTS5 全文搜索索引 → 调用 LLM 生成对话摘要存入 memory.json → WebSocket 发送用量统计。前端展示 Token 消耗。

    messages = context_compactor.compact(messages)

# 2. 组装 system prompt

# 4. 工具调用循环

        break
    elif response is tool_calls:

            result = registry.dispatch(tool_name, args)
            messages.append({"role": "tool", "content": result})

自动翻页机制

def paginate(arguments, default_page_size, fetch_fn):
    page_index = arguments.get("page_index")
    page_size = arguments.get("page_size", default_page_size)
    if page_index is not None:
        return fetch_fn(page_index, page_size)   # 单页返回
    # 自动翻页：不传 page_index 则循环获取全部数据
    all_records = []
    pi = 1
    while True:
        batch = fetch_fn(pi, page_size)
        if not batch: break
        all_records.extend(batch)
        if len(batch) < page_size: break  # 最后一页
        pi += 1
    return all_records

如何新增一个业务域

三步扩展，server.py 和 tools.py 无需修改：

  1. 在 handlers/ 下新建 new_domain.py，定义 schema 字典 + handle(client, arguments) 函数
  2. 在 handlers/__init__.py 中 import 并加入 ALL_HANDLERS 列表
  3. 完成！工具自动注册并可用

MCP 连接管理（Agent 端）

agent/tools/mcp_manager.py 负责管理所有外部 MCP Server 连接，将远端工具自动注册为 Agent 可用工具（命名规则 mcp_{server_name}_{tool_name}）。

特性实现
stdio 传输asyncio.create_subprocess_exec(command, *args)，JSON-RPC over stdin/stdout
HTTP 传输httpx.AsyncClient，POST JSON-RPC 到远端 URL
熔断器3 次连续失败 → 60s 冷却期，防止 Agent 反复重试断连服务
同步/异步桥接run_coroutine_threadsafe + blocking future，Agent 同步调度而 MCP 异步调用
启动自配置yonsuite MCP Server 在 FastAPI 启动时自动注入，无需手动添加

存储：data/memory/memory.json

触发：每次对话保存时调用 LLM 生成中文摘要（≤100 字）

注入：下次对话启动时注入 system prompt

目的：帮助 Agent 跨对话回顾历史上下文

摘要 100字 LLM

第 2 层：自主记忆 (fact_memory)

存储：data/fact_memory.json

触发：Agent 通过 memory 工具主动记录

分区："memory"（笔记）+ "user"（用户画像）

特点：冻结快照模式——会话开始加载快照，写入持久化但不影响当前快照

笔记 画像 快照

两者互补：摘要自动生成，记录"聊了什么"；自主记忆由 Agent 决定记录，存储"需要注意什么"（用户偏好、项目约定、经验教训）。接近字符上限（70%）时 Agent 自主压缩整理。

5.3 上下文自动压缩

agent/context_compactor.py — 每轮对话开始前自动检查消息量，超过阈值时触发压缩，防止超出 LLM 上下文窗口。

步骤逻辑
Token 估算CJK 字符 ~1.2 chars/token，ASCII ~3.5 chars/token，对齐 OpenAI tiktoken 近似
上下文窗口检测resolve_context_window(model_id) — 子串匹配 40+ 模型映射表，自动识别模型窗口大小
压缩触发消息 Token 数 > (窗口大小 - 预留输出空间)，保留最近 N 条消息，旧消息发送给 LLM 生成摘要
摘要注入生成的摘要作为 system 消息插入，替代被压缩的历史消息

配置入口：/settings/agent 页面 — 开关、窗口上限（自动/手动）、预留输出空间、保留最近对话量。

Hook 链机制

dispatch(tool_name, args):
    # before-hook: 可修改参数或阻止执行
    for hook in before_hooks:
        result = hook(tool_name, args)
        if result.__block__: return blocked_response

    # 实际执行
    output = tool_handler(args)

    # after-hook: 可修改输出
    for hook in after_hooks:
        output = hook(tool_name, args, output)
    return output

5.6 安全守卫

第 1 层：系统提示词

LLM 层面的语义约束，每次对话自动注入：

  • 绝不执行破坏性命令
  • 绝不修改系统关键路径
  • 绝不泄露密钥、Token、密码
  • YonSuite 写操作前先确认
  • 不将用户数据发送到外部网站

第 2 层：security_hooks.py（registry before-hook）

工具执行前的硬拦截（无法被 LLM 绕过）：

  • 拦截写入 /etc、~/.ssh、/boot、/System 等路径
  • 拒绝 rm -rf /、mkfs、dd、sudo 等危险命令
  • After-hook 审计日志记录

第 2.5 层（v1.1.1 新增）：SecurityEventExtension（事件层） v1.1.1

v1.1 引入 EventBus 后新增的冗余拦截，与 registry 层并行工作、复用同一份 deny 列表（agent/extensions/security_event.py 从 agent.tools.security_hooks import _DENY_WRITE_PATHS 和 _DENY_SHELL_PATTERNS，无重复声明）。

  • 同一份 deny 列表走两条独立 pipeline：BeforeToolCallEvent 上的 event.cancel(reason=...) + ToolRegistry 的 before-hook 链
  • 用户在 5.8 扩展管理页面停用 security-event 时，只关闭事件层，registry 层继续拦截 → 安全永不裸奔
  • M6+ 计划合并：registry 层改为订阅同一个事件，把双拦截收成单源

5.8 Extension 事件系统 & 配置化 v1.1.1

v1.1 引入的 EventBus + Extension 机制（借鉴 Pi 项目的扩展点设计）在 v1.1.1 完成配置化落地——用户可在 Web UI 上启用/停用每个 Extension，状态持久化到 config.json，运行时立即生效无需重启服务。

事件流：9 个扩展点

# run_conversation() 调用一次发出 9 类事件 session_start ──→ on_session_start user_message ──→ on_user_message (可改 event.content / cancel) ──── 循环开始 ──── before_llm_call ──→ on_before_llm_call (可改 event.messages / cancel) LLM 调用 after_llm_call ──→ on_after_llm_call (只读) ──── 如果 LLM 要求调用工具 ──── before_tool_call ──→ on_before_tool_call (可改 event.args / cancel) 工具执行（ToolRegistry dispatch + Hook 链） after_tool_call ──→ on_after_tool_call (可改 result / cancel) ──── 循环继续 / 结束 ──── session_before_compact ──→ on_session_before_compact (可追加 event.extra)

Extension 类 & Runner

class MyExtension(Extension):

    enabled = True

安全冗余双保险

v1.1.1 阶段 SecurityEventExtension（事件层）和 agent/tools/security_hooks.py（registry 层）并行工作：

  • 事件层通过 event.cancel() 在工具执行前阻断
  • registry 层通过 before-hook 链在 ToolRegistry 调度前阻断
  • 即使停用事件层（用户主动开关），registry 钩子继续工作 → 安全永不裸奔

M6+ 计划合并到单一事件层（5.6 安全守卫将只描述事件层 + 兜底策略）。

全文搜索SQLite FTS5CJK 字符级搜索，短关键词 LIKE 降级

8. 配置 & 启动

启动命令

# 一键启动（推荐）
./start.sh

# 或分别启动：
# 激活虚拟环境
source .venv/bin/activate

# 启动后端 (端口 8089)
uvicorn backend.main:app --host 0.0.0.0 --port 8089

# 启动前端开发服务器 (端口 8088)
cd web && npm run dev

# 快速验证工具注册
python -c "from agent.tools.registry import registry, discover_tools; discover_tools(); print('OK:', len(registry.get_all_tool_names()), 'tools')"

# 测试 MCP Server
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' | .venv/bin/python -m mcp_server.ys_mcp_server
